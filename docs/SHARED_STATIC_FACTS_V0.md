# Shared static-facts v0: restricted Java/Graal scalar importer

Status: **experimental/advisory**. This adapter is not a source compiler, a strict real-time verifier or a proof that the JSON was generated by a trusted compiler. It coordinates with the draft Java exporter [oreslang-source.java PR #1685](https://github.com/ores-truffle-oreslang/oreslang-source.java/pull/1685) and shared contract [oreslang-common-source PR #106](https://github.com/ores-truffle-oreslang/oreslang-common-source/pull/106).

## From real .ores source to the Rust reference analyzer

In a Java source checkout, with GraalVM/JDK Maven support:

```sh
mvn -B -ntp -Dtest=StaticFactsV0ExporterTest,StaticFactsCliTest test
mvn -q -DskipTests compile exec:java -Dexec.args="--static-facts path/to/scalar.ores" > scalar-facts.json
```

Then, in the Rust analyzer workspace:

```sh
cargo run --locked -q -p ores-analyze -- --static-facts /path/to/scalar-facts.json general
```

Be aware Maven/exec stdout may contain plugin progress unless quiet output is appropriately configured; the consumer intentionally fails closed on non-JSON input. To obtain clean source JSON, prefer the launched `OresMain --static-facts file.ores` command with classpath configured.

## Admitted source facts

The adapter deserializes `ores-static-facts/v0`, validates exact schema keys, SHA256-formatted *identity*, bounded collections, unique procedures and loop IDs, and known scalar-only call edges with `fanout=1`, `guard=unproved`. Any actor spawn, retry, callback, task, indirect call, taint/sink, permission or asserted loop termination/safepoint proof is an error. The JSON can only contain fact classes the limited Rust IR can conservatively represent.

The importer converts direct calls to existing Rust `Operation::Call` and unknown loops to `Operation::Loop { iterations: None, ... }`. It **forces allocation, copy and abstract compute bounds to `None`** instead of inferring zero from an incomplete AST. This means the Rust engine can detect recursive cycles (e.g. `ORES-SA102`) and unknown loop bounds (e.g. `ORES-SA104`), while correctly withholding numeric budget proofs.

`--static-facts FILE general` returns 1 on errors, 0 otherwise, 2 on malformed input. The response records `advisory_only=true`, `producer_authenticated=false` and `work_allocation_copy_bounds=unverified`. **Hard or soft profiles are denied at the command boundary with exit 2** rather than allowing an unverifiable source hash to become a production admission ticket.

This importer is intentionally not a competing full implementation of the shared Python analyzer; it reuses the existing Rust operations engine for the supported scalar-call and loop subset. The Python model remains the schema/conformance oracle for amplification, security and callback timing while richer compiler-issued IR and backend facts are implemented.

## Exact-head local gate

The committed integration script accepts two *existing authorized local checkouts*:

```sh
EXPECTED_JAVA_HEAD=<reviewed-java-sha> \\
EXPECTED_RUST_HEAD=<reviewed-rust-sha> \\
bash scripts/test-java-static-facts-roundtrip.sh /path/to/oreslang-source.java
```

It emits the checked-out Git HEAD values, requires them to match the optional
reviewed commit SHAs, verifies source byte hashes, exercises recursive and
scalar source programs, and requires a **2 (rejected)** exit from
`ores-analyze --static-facts ... hard`. Rejections remain required even if
the scalar program has no visible resource effects: compiler provenance and
lowering completeness have not been authenticated. If expected SHAs are
unset, the gate prints the actual heads but does **not** establish that they
match a reviewer-approved source revision.

Limits are 512 functions, 8,192 direct call edges, at most 256 loops/procedure
and 4,096 loops/document. Corresponding Java exporter branch PR #1685 now
enforces the same limits, and rejects duplicate caller/callee callsites and
calls inside loops, because the current v0 edge format does not preserve
callsite multiplicity or enclosing-loop work effects.

## Six-backend exact-commit integration gate

The `scripts/verify-cross-backend-static-facts-v0.py` executable smoke requires
**three locally authorized, already checked-out private repositories**, a real
backend compiler, and a real Rust analyzer. It does not clone or mirror code,
read GitHub tokens, trust an org carrier, or treat an absent runner as PASS.

Install Python `jsonschema` (Draft 2020-12) in the runner environment and the
backend's real toolchain. A reviewer must obtain the three expected 40-character
commit SHAs independently before invoking the gate; **do not infer approval**
from a script that substitutes today's checkout HEAD for those arguments:

```sh
python3 scripts/verify-cross-backend-static-facts-v0.py \\
  --backend js \\
  --producer-repo /authorized/oreslang-source.js \\
  --analyzer-repo /authorized/oreslang-static-analysis.rs \\
  --contract-repo /authorized/oreslang-common-source \\
  --producer-head <reviewed-JS-commit> \\
  --analyzer-head <reviewed-analyzer-commit> \\
  --contract-head <reviewed-contract-commit>
```

The `--backend` choices are `js`, `rs`, `net`, `forge`, `llvm`,
`wasm`. Forge, LLVM and Wasm require a **previously authorized local native
compiler executable**, and now require `--backend-compiler-sha256 <independently-reviewed-64-hex-digest>`.
Pass `--backend-compiler /absolute/path` for an explicitly selected executable;
Forge and LLVM can use the local CMake compiler from `build/`. Wasm always
requires `--backend-compiler` because it runs the actual native
LLVM→Clang→Wasm producer bridge, and the expected digest is forwarded into
that bridge. Binding compiler bytes **still does not prove** they were
compiled from the reviewed Git commit; trusted build provenance remains needed. It does not manufacture missing compilers,
simulate a toolchain, or fetch private source into another organization.

A genuine PASS requires, in sequence: exact clean reviewed Git checkouts,
pinned native compiler bytes when applicable, byte-for-byte source
identity; the real compiler's emitted JSON; validation using the exact
reviewed schema; canonical `main/0` with **no falsely invented effects**;
the real Rust `general` report with `advisory_only=true`,
`producer_authenticated=false`, and *all three* work/copy/allocation bounds
`null`; both soft/hard profiles rejected with exit 2; unresolved-call source
rejection; tampered source identity and invalid/replaced proof rejection; and
an unproved synthetic loop yielding `ORES-SA104`. A rejected
`enclosing_loop` call verifies that flat calls never erase multiplicity.

This tests the one-function literal-only common intersection, not the
non-scalar extensions. Each backend's richer actor/task/async/ownership
lowering must be tested separately when representable in a typed shared IR.

**No end-to-end PASS is claimed for a registered but unexecuted script.**
The current source-org Actions jobs have returned zero steps and missing job
logs. CI infrastructure recovery or a locally authorized exact-head toolchain

It operates only on two existing local checkouts and **does not copy private source across GitHub organizations**. This runner is committed but **not executed in this session**; it must be run on authorized CI with real executed steps.
